# Plastic Molding Chamber

## Modeling and locking

Placing a <ref item="anvilcraftplasticraft:plastic_molding_chamber"/> reserves a 3x3x3 forming region behind it. The editor represents the ordinary 48x48x48-unit workspace at 16 internal units per block. The editable projection has no collision and appears as one translucent hologram like a construction blueprint: overlapping cubes do not stack darker, and the solid 3D form and negative spaces stay the same as the opaque model. Oversized projections use their exact outer bounds. In Casting mode, all 27 region blocks gain full collision atomically when clay filling actually begins, while the frozen model projection remains visible throughout the three clay layers. 3D Printing never enables clay-mold collision. In Printing mode, all 27 region blocks share one 3x3x3 cabin selection outline so looking into the cabin does not draw a one-block box.

Undo is available only when the current editing session has history. Copy and Cut require at least one selected cube, while Paste requires a cube in the clipboard. These buttons activate when the left mouse button is released over the same button; dragging away before release cancels the action. With multiple cubes selected, the gizmo sits at their combined bounding-box center and every tool acts on all selected cubes. Moving translates each cube together with its pivot, while ordinary rotation still uses each cube's own pivot. Center Pivot assigns the combined center to every selected cube, so subsequent rotation carries them around that shared point without changing their relative layout. Each cube button in the right-hand element list shows its full name followed by its current Visible/Hidden and Unlocked/Locked states, including inherited group state. Delete All Cubes in the workspace context menu removes every cube as one undoable edit. If any cube is locked, the model remains unchanged. Cube numeric fields apply the typed value when Enter is pressed or when another click removes focus. Long type names in the type-assignment overlay scroll inside their buttons the same way as model-management names.

The right-hand element list follows Windows file selection: a plain left-click selects only that button, Ctrl-click toggles one button while preserving the others, Shift-click selects the continuous range from the last anchor, and Ctrl+Shift-click adds that range to the current selection. Direct cube selection inside the modeling viewport keeps its existing behavior.

A model needs at least one volumetric or zero-thickness cube before it can be locked. Locking freezes the current revision and calculates the resources for the forming method detected from the chamber structure. Casting accepts an outer span of at most `48 px` on each axis. Printing accepts only models completely inside `x/z=[8,40]` and `y=[1,33]`, a `32x32x32 px` volume. In Printing mode, the main modeling grid remains at `y=16`, while the gray workspace outline and world guides use those bounds; the central `16x16 px` fine grid and red/blue axes stay in place. The editor also shows the printing component, the dedicated GUI print-chamber model, its doors, and all three moving axes. Every model is rendered intact without camera-facing cutaway filtering. A model outside the current forming method's range can still be loaded and edited, but Lock and Start Processing keeps its initial plus icon, is disabled, and explains the size limit in its tooltip. The same disabled state applies when a functional type fails validation or a high-precision type has no printing component. A player, item, or other entity in the forming region holds the machine at "region blocked" without consuming resources. It retries after the region is clear.

Multiphase Transcendium in the resource slot bypasses functional-type validation only; it never bypasses the current forming method's size limit. When the model actually needs this override, the second lock-confirmation click consumes `1`; an ordinarily valid type consumes none, and unlocking never refunds a committed item. Continuous mode rechecks and consumes the required Multiphase Transcendium for every cycle.

## Structure Disks and shared blueprints

The GUI disk slot accepts only AnvilCraft Structure Disks; ordinary disks cannot be inserted. Store to Disk works whether the current model is editable or locked. One click writes an empty Structure Disk. A disk with a block structure, molding model, or other data first shows a title-bar warning and is cleared and replaced only after a second click. A successful store embeds the canonical blueprint and its SHA-256 hash while atomically writing a shared JSON copy under `<world>/anvilcraftplasticraft/blueprints/`. The embedded copy still loads when the shared file is missing or damaged.

An ordinary Structure Disk keeps AnvilCraft's existing tooltip, Smart Block Placer `5x5x5` check, and rotating block-structure preview. When a Structure Disk contains a molding model, its hover window rotates that model at the same speed and centers it from its exact bounds. Structure shows the model name, Size shows the fully manufactured X, Y, and Z dimensions in blocks, and the final line becomes either a green processing confirmation or a red "Model is too large to process" notice. Molded plastic items use the same size calculation and show at most four necessary decimal places.

The model management overlay starts closed whenever the GUI opens and shows up to six shared models per page. It renders one button per actual model and no empty model buttons. Each row shows the shared JSON filename without its extension, so renaming a file in the blueprint folder updates the list after Refresh. Search filters filenames, model names, and owners. Long lists scroll vertically, while long names scroll within their row. A left-click selects that entry and writes it to the current Structure Disk; it never changes the chamber model directly. Without a Structure Disk, the selection remains for the current GUI session. A right-click starts an inline rename; Enter or clicking elsewhere confirms it and updates both the filename and the blueprint name. Replacing different disk data shows both names and hashes and requires a second click on the same row. Load, Store, the model management toggle, and the four bottom overlay actions activate only when the left mouse button is released over the original button; dragging away before release cancels the action.

Load Disk is the separate action that moves a Structure Disk blueprint into the editor, always unlocked and editable. Loading requires an editable machine with no molded clay and no melt in the forming batch. The 8 B staging tank may remain filled and is never changed. A model over `48 px` on any axis also loads at its original size and remains available for inspection and editing, but cannot be locked. Replacing the current draft still requires confirmation.

The shared library holds at most `512` models. Shared files record the UUID and name of the player who saved them. Every player may view and load them; only the owner or an administrator with permission level 2 or higher may overwrite, rename, or delete one. Pins are stored separately per player and world. Copy creates a non-conflicting file with identical model content owned by the player who copied it. Clicking Delete without Shift only shows the title-bar requirement; holding Shift and releasing over Delete removes the model immediately. Deletion does not affect copies already embedded in disks or loaded into chambers.

## Importing from the model folder

The same button at the bottom of model management is the import entry and remains available with no shared model selected. A normal Refresh Models click scans the directory once without opening a file manager. Shift-click opens the model folder without scanning or importing. In a local world it locates the authoritative world library above. On a remote server it uses a safe client directory and, before a Shift-open, exports the selected model there as a read-only copy that is not uploaded again. If the file manager cannot be opened, the absolute path is copied to the clipboard.

After placing a `.json` or `.bbmodel` file in that directory, use a normal Refresh Models click to read that scan's files and send them to the server. The GUI never scans in the background. Once the server confirms that a model is stored in the shared library, the client deletes the source only if its size and modification time still match the uploaded file; failed or replaced sources remain. A file is limited to `1 MiB` and `64` JSON nesting levels. Path traversal, symbolic links, other extensions, and files with no local `elements` that depend only on an unavailable external parent are rejected. Uploading the same owner, name, and model hash again does not create a duplicate.

Minecraft Java imports support `elements`, `from`, `to`, single-axis `rotation`, and `origin`. Local `elements` are imported directly and take precedence over `parent`; recognized vanilla full-cube parents expand only when local geometry is absent. Blockbench imports support cubes, groups, pivots, and rotations. Except when an exact `48 px` Blockbench span is fitted to the complete workspace, Java and Blockbench source coordinates both map to chamber display coordinates, so `(0,0,0)` remains numeric `(0,0,0)` after import. Zero-thickness planes remain zero-size cubes. UVs, textures, colours, animation, and display transforms are omitted. Meshes, locators, rotation rescaling, plugin-private elements, and other shapes that cannot be converted losslessly identify the unsupported item and reject the complete import.

Imported bounds may exceed `48 px`. Oversized models retain their source dimensions in the shared library, can be written to Structure Disks, and can be loaded into the chamber for inspection and editing, but cannot be locked or processed. A model no larger than `48 px` per axis but outside the workspace is never scaled. The GUI first shows a suggested whole-model translation; another normal Refresh Models click confirms the import with that offset. A file change invalidates the pending confirmation.

## Power and casting clay mold

The chamber consumes AnvilCraft grid power at a fixed 256 kW working level. Its internal 160000000 FE buffer matches one super capacitor. The crafting recipe accepts either a charged or empty super capacitor: a charged input gives the crafted chamber 160000000 FE, while an empty input gives it 0 FE. Stored FE keeps the machine running after the grid disconnects. When FE runs out, clay animation, melt pumping, and printing scans pause in place while clay, fluids, animation or printing progress, and mold collision remain intact. The GUI resource slot also accepts charged capacitors and super capacitors, consumes at most one per gt, and adds their full 8000000 FE or 160000000 FE charge only when the buffer has enough room. The empty capacitor remains in the slot when the input stack is exhausted; otherwise it returns to the active player's inventory and drops beside the chamber if that inventory is full.

The resource-slot tooltip lists capacitor charging, bucketed plastic-melt filling, and Multiphase Transcendium type bypass in that order. While Multiphase Transcendium is active, the Lock and Start Processing button gains a bright-purple one-pixel inner border and rising purple particles. The border becomes lighter on hover, and its top edge sinks by `1 px` while the left mouse button is held.

The filter slot permanently accepts clay balls only and is used only by Casting. It uses the chute-style ghost item, translucent red overlay, and red limit number. Scrolling over the slot changes its effective stack limit from 1 to 256, with a default of 256; the slot bypasses the clay ball's normal limit of 64. Every 40 gt (2 seconds), the chamber attempts to collect dropped clay balls from the rear `3x3x3` forming region and the complete `5x5x5` volume made by extending it one block on every side, placing them directly in this slot. Collection stops at the currently configured stack limit. Lowering the limit never deletes existing items. If the current stack is above the new limit, automation may extract it but cannot insert more.

For solid model volume `V` and `B` cubic pixels in the active baked bounding space, each Casting cycle requires:

`ceil((B - V) / 1024)` clay balls

For the ordinary `48x48x48` workspace, `B` is `110592`; oversized models use their integer outer dimensions. Cavities also require clay, while zero-thickness cubes do not reduce the requirement. Casting fills for 12 active game ticks. At gt 4, 8, and 12, the machine atomically consumes enough clay to reach one third, two thirds, and the full requirement, then renders one complete 3x3 layer. Missing clay or power stops before the next complete layer, with no partial deduction or interpolated jitter. The ordinary workspace has a maximum requirement of 108 balls, so the default slot capacity can hold a whole batch; players may instead lower the limit and keep it supplied through automation. Manual unlock first returns molded clay to the filter slot, then drops any remainder in the forming region. A forming batch automatically returns to staging when all of it fits; only insufficient staging space requires extraction through the top first.

## Forming methods and propellers

The GUI has no forming-method control. A 3D Printing Component exactly one block above the chamber makes every product use 3D Printing; without that component, the chamber uses Casting. Right-clicking the 3D Printing Component also opens the chamber GUI. This structural choice remains independent of the Continuous, Redstone, and Single production modes. Each cycle freezes the forming method detected when it locks and never switches methods midway. Removing the component after the print head starts immediately interrupts the batch, clears its visible construction and progress, and returns the chamber to the editable stopped state. Reinstalling the component requires locking again to begin a complete new cycle.

High-precision types require a <ref item="anvilcraftplasticraft:plastic_3d_printing_component"/> exactly one block above the chamber itself. Without that component, Lock and Start Processing receives a gray disabled overlay, ignores mouse input, and does not change its texture frame on hover. Its tooltip reads "High-precision types require a 3D Printing Component." Installing the component automatically selects 3D Printing, so high-precision types cannot be cast.

Propeller is the first high-precision type and currently adds only a type identity, with no special behavior. Its XZ projection must fit entirely inside the central `16x16 px` block, span at least `8 px` along either X or Z, and be no thicker than `2 px` on Y; zero-thickness surfaces are valid. A zero-thickness cube contributes the pixel centers covered by its real XZ quadrilateral instead of an expanded bounding rectangle. The center must cover a complete `2x2 px` core. Branch separation ignores the shared `1 px` root around that center; the remaining projection must leave at least two separate branches of at least `2` pixels each, and occupancy of the central footprint must remain below `85%`, preserving gaps instead of accepting one solid sheet. The type button uses a bundled modified copy of `untitled-2`: the geometry of all three cubes is moved upward together by `4 px`, their shared intersection-center pivot moves with them to `(24,21,24)`, and the icon never reads the blueprint file at runtime. The Allay Hard Hat type button likewise uses a bundled orange copy of the `hard-hat` geometry and never reads the world blueprint library, so deleting a player's `hard-hat.json` does not remove the button icon.

## Staging melt, casting batch, and component storage

The top and bottom faces expose only the same fixed bidirectional fluid interface and no clay item capability. The four horizontal faces expose only the clay item capability and no fluid capability. The chamber's 8000 mB staging tank accepts compatible plastic melt in every machine state, including editing, no power, no clay, processing, and waiting. Its transparent body tank uses the stored melt's texture and colour, with the surface height proportional to the current mB amount out of 8000 mB. The 3D Printing Component has a fixed 8192 mB capacity, uses a dedicated model with a translucent animated screen while powered, and switches to the unpowered appearance in sync with the chamber. Its transparent tank maps the current amount against 8192 mB across the complete inner height and leaves a tiny gap from the glass walls. The GUI resource slot empties at most one compatible plastic melt bucket into staging per gt and handles its empty bucket like an empty capacitor. Right-click the GUI gauge with a matching plastic melt bucket on the menu cursor to empty it, or with an empty bucket to fill it; the player's main hand is not used. A mismatched fluid, colour, component set, or insufficient capacity changes neither the container nor the machine. The gauge tiles the tinted `16x16` fluid texture at its native height: each 4 B shows one complete tile and 1 B reveals only its bottom quarter.

When a casting mold is complete, the structure is valid, and power is available, up to 250 mB moves from staging into an independent forming batch each gt. For 3D Printing, the chamber likewise pumps melt at 250 mB/gt into the internal tank of the component above it once the model is locked and the structure, component, and power are available. The casting batch and printing component both store the complete amount required by one product of volume `V`:

`M(V) = max(ceil(V / 4), 250) mB`

Staging and either the casting batch or component storage do not overlap. An ordinary solid `48x48x48` casting model requires 27648 mB, so its casting batch plus the 8000 mB staging tank can hold 35648 mB total. The largest printable solid occupies `32x32x32 = 32768` voxels and requires 8192 mB, so its component plus staging can hold 16192 mB total. The first melt entering the product storage fixes its fluid, material, colour, and component identity until empty. Extraction through either vertical chamber face drains the unprocessed casting batch or component storage before staging.

Casting by anvil requires at least 250 mB already inside the forming batch. Staging melt does not satisfy this threshold and is never moved into the batch instantly by an anvil strike. 3D Printing must first fill the component to the complete `M(V)` amount and does not start early when it reaches the 250 mB casting minimum.

## 3D Printing

A printing cycle never enters clay filling, plays no clay-fill animation, and reserves, consumes, or returns no clay balls. Once the chamber has pumped the complete product amount into the component, printing starts automatically as soon as the forming region is available. The complete process ignores Giant Anvil processing and requires neither Crafting Tables nor a Space Overcompressor above the forming region.

Each complete cycle emits a purple F note above the chamber and plays an F-pitched note-block bell: casting triggers it when the Giant Anvil successfully creates the output, while printing triggers it only after the product has left, the doors have fully closed, and another cycle may begin. The first stall caused by missing clay, melt, power, component, structure, or clear region instead uses an F-pitched note-block bass; casting also uses it when a ready batch first begins waiting for a Giant Anvil. One unchanged stall does not repeat every gt, but a later stall after recovery plays again.

Before physical printing starts, Printing mode keeps the model's world surface projection together with the reduced grid, axes, and workspace guides. The projection is hidden as soon as the print head starts working and returns only after the product has dropped and the doors have fully closed. The block-entity renderer loads the dedicated printer frame and three axis models. Every forming-region block uses that same 3x3x3 cabin as its selection outline, so the crosshair outline sits on the cabin exterior instead of a one-block box in the interior. At rest, the assemblies park `16 px` above the modeling display origin `(0,0,0)`, leaving room for the projected model. The red X assembly travels east-west and carries the blue Z assembly; the green Y assembly travels up-down and carries both X and Z; Z travels north-south by itself. Scanning begins at the lowest Y layer. Z prints one complete row, X moves `1 px` east, and Z prints the next row in reverse. This snake path completes the layer before Y raises the other two axes by `1 px` and printing continues.

The three assemblies use smooth acceleration and deceleration between targets, with longer travel taking proportionally longer instead of teleporting. A voxel begins processing only after the print head reaches it. The component consumes at most `1 mB` from internal storage during each active processing gt, and a voxel joins printing progress only after receiving its complete material share. The scan includes every voxel with a positive-volume intersection against a volumetric source cube instead of relying only on voxel-center samples. Construction display keeps each source-cube face as a continuous plane over the completed voxels, drawing only the real intersection of that face with printed pixels instead of filling a convex web to a distant corner. Temporary caps close every boundary against unprinted neighbours so the work never appears hollow or striped from above or from a completed side. Those caps disappear when their neighbouring voxels complete. After the final voxel, the assemblies first return smoothly to their default origin while the construction retains the frozen batch colour, then a complete plastic entity of that same colour takes over. The two bottom doors move apart by `16 px` each. The product regains gravity only after the doors are fully open. During discharge the forming region keeps its selection and collision for everyone except that printed plastic entity, so a player standing on the cabin does not fall in. A block below may hold the product and keep the doors open. Once the product's complete collision bounds leave the `3x3x3` forming region, the doors close; manual, redstone, and continuous cycles remain blocked until the tick after they are fully closed.

## Giant Anvil casting and clay recovery

Casting requires a 3x3 platform directly above the top layer of the forming region and a Giant Anvil landing on that structure. Nine Crafting Tables perform a conversion and create a shape-preserving plastic entity inside the original 3x3x3 region. Eight outer Crafting Tables with a Space Overcompressor in the centre perform crafting and create a plastic item drop in the same region. A complete product retains each source cube, endpoint, and rotation instead of displaying the manufacturing cells as a stepped outline. The platform is derived from the chamber orientation and region anchor, so all four horizontal chamber directions use the same rule. Crafting Tables, the Space Overcompressor, the chamber, and its region blocks are never consumed.

An ordinary casting strike succeeds only when the structure is correct, the clay mold is complete, the chamber can maintain its 256 kW working level, and the forming batch contains at least 250 mB. Duplicate delivery of one landing event cannot produce a second result, and printing cycles explicitly ignore landing events.

Multiphase Transcendium retains the selected functional type and derives its maximum attributes from the model's complete outer volume instead of scanning its real cavity. A chest gains `1` slot per `64` cubic pixels. For example, a solid `8x8x8 px` cube has no cavity, but Multiphase Transcendium can force it to be a chest with `512 / 64 = 8` slots.

A tank forced through type override still derives its capacity from the complete outer volume and can store, receive, and extract fluids normally, but its entity renders neither internal fluid volume nor a free surface. Its contents remain visible through capabilities, Jade, and the anvil-hammer overlay.

Casting conversion is fixed at `1 mB = 4` forming cells, so 250 mB pays for at most 1000 cells and 251 mB for at most 1004. The machine divides the paid cell count by the model's total cell count, then places one horizontal cut at that percentage between the model's lowest and highest Y coordinates. Source cubes below the cut retain their endpoints, rotations, and continuous slopes; cubes crossing it are clipped at the same height and receive a flat upper surface, while everything above it is removed. Cell order is stable accounting data and is never rendered as scattered pieces. A model of at most 1000 cells becomes complete at the 250 mB minimum. A purely zero-thickness model retains all surfaces after meeting that minimum; zero-thickness cubes in a mixed model follow the same height cut without creating caps. Printing never uses partial-material clipping and produces the full model only after the component's complete stored amount has been consumed.

A successful strike clears only the forming batch. The fluid identity, components, and exact mB amount in the 8 B staging tank stay unchanged. Products are created in the forming region rather than stored by the machine. Every clay ball actually committed to the mold drops back into that same region, merged into stacks of at most 64 where possible: batches that used 1, 64, or 108 clay balls return exactly 1, 64, or 108. Clay-breaking particles are visual and do not alter the recovered count.

## Production modes

- Continuous processing keeps the model after each success. Once the region clears, Casting prepares another clay mold and waits for another valid anvil strike, while 3D Printing automatically refills the component and directly prints the next product. Required override items are checked again for every batch
- Redstone control is the default and starts one complete cycle for each rising edge while unlocked. A steady high signal never retriggers; Casting waits for a new edge before preparing another mold, while printing waits for a new edge before refilling the component
- Single processing manually locks one complete cycle, returns to editing when its product is complete, and ignores redstone locking. Casting still completes by anvil, while printing completes automatically after its component is full

All three production-mode buttons take effect immediately while locked, processing, or discharging. They never cancel the current product, change its frozen forming method, destroy its mold, or refund resources, but completion immediately uses the latest selection to either queue a continuous next cycle or return to editing. Switching an already waiting continuous machine to Redstone or Single immediately cancels that pending cycle. While the discharge doors are still open, selecting Continuous immediately queues the next cycle and selecting either other mode immediately removes that queue. In addition to generic resource bars, Jade shows the current state and forming method; a printing cycle also shows completed and total voxels instead of describing its progress as clay work.
