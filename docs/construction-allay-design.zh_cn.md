## 1. 施工悦灵、安全帽与工种

### 1.1 戴帽转换

玩家手持成型类型 `allay_hard_hat` 的通用塑料，右击原版 `Allay`，转换成 `working_allay`。潜行右击戴帽悦灵摘帽，转回原版悦灵。UUID、位置、朝向、自定义名称和主手物品保留。所有者在戴帽时记为当前玩家。

摘帽时若仍有托管携带物或收集库存，拒绝摘帽。死亡掉落安全帽、主手工具、收集库存和托管携带物。高粘性树脂块、树脂铁砧不得捕获 `WorkingAllayEntity`。

没有工人物品、装配配方、铁砧锤回收或创造变体选择器。世界中只注册一个施工悦灵实体类型。

### 1.2 安全帽

成型类型 `allay_hard_hat` 替换已删除的 `propeller`。校验只限制占地和高度：模型非空、水平外接不超过 `11×11` px、高度不超过 `16` px，不要求落在工作区中心。原因键：`allay_hard_hat_empty` / `allay_hard_hat_too_wide` / `allay_hard_hat_too_tall` / `allay_hard_hat_model_required`。需要 3D 打印组件。戴上后按模型原尺寸渲染，水平中心对齐头顶中心；头骨原点在头底，先上移 `5 px` 到头顶，再把帽底沉入 `1 px`，看起来是戴进去而不是搁在顶上。

材料能力目前只预留 `FIRE_RESISTANT` 边界，耐热塑料尚未加入。一顶帽子具备某种材料特性，整只戴帽悦灵就获得该特性；后续新材料只在 `AllayHardHatTraits` 注册，不在实体类内逐种硬编码。

### 1.3 工种只看主手

工种不得写成实体类内不断扩张的 `switch`。实现时建立服务端 `AllayToolDefinition` 注册边界，每项至少声明稳定资源 ID、匹配的主手物品、支持的任务能力、触及距离、内部库存布局、服务端动作执行器及需要同步的显示状态。工种 ID 不存盘，由主手物品在加载后解析。

空手或未知物品是通用工，不是“只悬停”。当前注册项：

| 主手 | 定义 ID | 当前能力 | 触及 | 内部物品库存 |
| --- | --- | --- | --- | --- |
| 空手 / 未知物品 | `none` | 取料、携带、施工投影交付、临时流体封堵、近距收集 | `1` 格 | 普通方块同材最多一组；特殊交付单件 |
| 蟹钳 | `construction` | 取料、携带、施工投影交付、临时流体封堵 | `4` 格 | 普通方块同材最多一组；特殊交付单件 |
| 切石机 | `demolition` | 瞬间真实拆除 | `1` 格 | 无 |
| 手持磁铁 | `collection` | 收取任务掉落物或自由吸入物品并卸载 | `9` 格 | 九格临时库存，卸货时必须尽力腾空 |
| 望远镜 | `observation` | 加载自身所在区块及水平相邻八个区块，并在任务中引导机群 | `0` | 无 |

调度器按能力叠加，不按实体类型派发。空手通用工同时能建设和近距收集；蟹钳取消收集；切石机只拆除；磁铁只收集；望远镜只维持九区块实体刻覆盖并按任务窗口移动，不领施工操作。空手可以放普通单格以及门、床、成对大箱子这类两格件；巨型铁砧等多方块和超过 1 格宽或 2 格高的塑料实体必须蟹钳。

以后加入剪刀、钓鱼竿、打火机、刷子和护符盒时，只新增工具定义与对应任务执行器，不改变悦灵实体的保存格式、飞行器或渲染器。AnvilCraft 多用途工具以后作为一个复合工具定义，可以在领取任务时从其已声明能力中选择除拆除以外的任一动作。切石机拆除保持独占能力，避免绕过拆除阶段、掉落和权限规则。

### 1.4 实体、飞行与交互

`WorkingAllayEntity` 继承原版 `Allay`，关闭原版拾取与复制，任务中关掉原版大脑。空闲且未被指挥时复用原版游荡大脑与飞行动画，不再锁在 `5×5×5` 格里，也不强制离地四格悬停。

飞行状态只有 `HOVERING` / `FLYING` / `DOCKING`。没有落地态。`setNoGravity(true)`。碰撞箱与原版悦灵相同：`0.35 × 0.6`。`canBeCollidedWith()==false`，玩家不能站上去；`isPushable()==true`，可以被挤开；可以拴绳。

取料、放置、拆除、收集和卸货每 `4 gt` 最多 1 次；够到后先转向玩家或目标，对准后才动手。建设取普通 PLACE 方块时每趟只取同物品、同组件材料，合计不超过该物品的一组；方块实体内容、流体、实体与会返还物品的材料仍逐项事务。正在取料、放置、拆除、收集或入库时由工种调度器与三维寻路驱动，不会一边干活一边乱跑。

施工悦灵本身没有设置界面，也不能单独改暂停或跳过。只有绑定了已加载休息室的悦灵跟随该休息室的缺料与缺拆除策略；没有绑定休息室的世界悦灵固定 `PAUSE`。空白格清场策略不按悦灵存储，只属于认领该任务的协调室；玩家从 GUI 手动放出的悦灵会清空休息室、来源休息室和转运任务绑定，成为无休息室悦灵，不会主动钻回原室。

实体、休息室托管记录之间不得丢失安全帽、主手工具、设置、来源休息室、所有者、任务托管物或收集库存。拆除和观察永远没有携带物槽；拆除不会吸取、收集或转运被拆方块的掉落物。

## 2. 蓝图、结构磁盘与中央施工任务

一个已经放到世界中的蓝图对应一个服务端权威 `ConstructionJob`。蓝图保存“要建什么和放在哪里”，任务保存“谁在建、资源从哪里来、流体封堵与拆除进度、任务生成的掉落物、哪些操作已交付、哪些被跳过以及当前提交状态”。悦灵只持有短期分配，不把整份蓝图复制进每只悦灵。

蓝图默认只放置投影而不启动。一个玩家可以放置任意数量的蓝图，但同一时间最多启动一份；启动新蓝图会暂停该玩家先前启动的蓝图。这个限制是“每名玩家一个活动任务”，不是全服务器只能有一份任务。非活动蓝图只保存和渲染必要信息，不保持区块加载，也不吸引悦灵。

悦灵和休息室归制造或放置玩家所有，只参与所有者或同一 FTB Teams 团队成员的任务。FTB Teams 支持放在独立可选集成类中，通过其公开 API 查询当前团队关系，公共任务入口不直接初始化 FTB Teams API；未安装 FTB Teams 时退化为仅所有者授权。不同所有者且不在同一 FTB Teams 团队的活动蓝图不能争抢悦灵，远程转运、自由收集卸货和任务材料访问也不能越过该边界；权限检查属于服务端任务分配条件，不由客户端 GUI 决定。团队成员变化后在下一次派发、卸货或世界交互前重新校验，不能把已经离队的授权永久缓存进悦灵 NBT。当前由 `ConstructionPermission` 统一实时复核团队关系和世界写入权限；世界权限默认使用原版玩家可交互判定，领地集成通过窄 provider 接入。

蓝图在世界中的部署、锚点移动、旋转、镜像、确认和分层投影交互以 Create 蓝图体验为基准，使用 Plasticraft 自己的贴图、颜色和状态表现，不照搬 Create 美术资源。结构磁盘只改变蓝图数据和任务状态，不把 Create 作为运行依赖。

首次部署和每次重摆都先校验完整变换后的蓝图包围盒：所有目标格必须位于当前维度可建造高度与世界边界内，并且不得与同维度其他已部署施工任务相交；失败分别报告 `placement_out_of_world` 与 `placement_overlaps_job`。已有实际施工进度或仍处于活动状态的任务禁止移动。尚无实际进度的暂停/未启动任务可以移动；移动时清除旧位置的方块与实体投影索引并重置坐标相关计划，保留既有休息室协调站，下一次启动在新锚点重新规划。

结构磁盘与部署任务之间使用稳定的任务 UUID 和蓝图内容哈希关联。已经部署的结构磁盘在任何能够容纳它的菜单槽中都按任务状态由程序直接绘制纯色槽底：黄色表示未启动或已暂停，绿色表示已启动，不读取专用槽位贴图。右击该磁盘槽会覆盖该槽原有的拿取、拆半或快捷交互，直接启动对应任务并暂停玩家的其他任务；启动没有按钮或图标。槽底属于 `ItemStack` 的客户端显示状态，因此磁盘移动到玩家背包、箱子或其他菜单槽后仍跟随磁盘。休息室有独立任务磁盘入口：已部署磁盘进入槽位只认领该室为唯一协调站，槽底保持黄色；空手右击才黄底变绿并启动，同时暂停所有者的其他任务。抽盘、破坏或取消会解除认领。

休息室认领任务后：

- 附近无休息室建设、拆除和观察悦灵都退出该任务，无休息室建设悦灵不再从玩家身上取料；无休息室收集悦灵继续执行自己的自由拾取模式，不领取中央任务租约，但仍可像玩家或漏斗一样独立拿走范围内掉落物，任务台账把这部分记为外部结算
- 已经取料的无休息室悦灵先回到来源玩家身边返还物品，再退出任务
- 本室和远程调来的悦灵都只从任务休息室下方物流库存取得蓝图材料与临时流体填充块；任务掉落物由收集悦灵送回任务休息室指定卸载端
- 磁盘离开任务休息室或任务被暂停时停止继续派发，已在途资源按任务台账返还；玩家显式取消则执行第 3 节的按进度提交

当前无休息室闭环已经实现：建设/拆除/收集从所有者背包取料或向所有者卸货；创造模式所有者不扣物品，蓝图需要的任何材料都能无限取。

任务至少具有以下状态，状态转换只由服务端完成。`ConstructionJob.state` 字节值冻结，新状态只能追加：

| 状态 | 字节 | 含义 |
| --- | --- | --- |
| `INACTIVE` | `0` | 投影已放置但未启动，不派发、不加载整个蓝图区域 |
| `ACTIVE` | `1` | 已启动的冻结兼容值；计入进行中，新启动写入 `PLANNING` |
| `PLANNING` | `2` | 解析结构、扫描原有方块与流体、生成拆除/材料/观察点清单并复核权限和可达顺序 |
| `WAITING_PERMISSION` | `3` | 任一计划操作被领地或权限系统拒绝；不允许按“跳过”继续，等待权限恢复或玩家取消 |
| `WAITING_OBSERVER` | `4` | 下一项所需区块没有其他实体刻级加载来源，且暂时没有观察悦灵能够建立连续的九区块覆盖窗口 |
| `SEALING_FLUID` | `5` | 建设悦灵真实放置临时填充块，一次封堵计划范围内会再生或回流的流体片区 |
| `DEMOLISHING` | `6` | 拆除悦灵按切石机砸击语义真实清空蓝图声明区域内的原有方块和区内填充块 |
| `COLLECTING_DEBRIS` | `7` | 有可用任务收集悦灵时执行一次有界清场；没有收集能力、库存满或卸载受阻的剩余掉落物留在世界，不阻塞建造 |
| `WAITING_DEMOLITION` | `8` | 存在可拆方块但缺少拆除悦灵，按暂停策略等待玩家处理 |
| `BUILDING` | `9` | 正常取料、飞行并交付施工投影 |
| `WAITING_MATERIAL` | `10` | 缺料策略为暂停，相关悦灵悬停等待 |
| `SOURCE_UNAVAILABLE` | `11` | 玩家、下方容器或返还出口暂时不可用；相关悦灵立即悬停并保留任务租约和携带物，来源及加载覆盖恢复后续做 |
| `COMMITTING` | `12` | 材料交付结束，区域锁定并执行安静提交 |
| `COMPLETED` | `13` | 完整结构提交成功 |
| `COMPLETED_INCOMPLETE` | `14` | 存在缺料、按配置跳过的缺工种、不可拆障碍或不可达位置，残缺结构已经自动提交 |
| `STOPPED_PARTIAL` | `15` | 玩家取消任务，已交付投影已经提交，拆除结果和部分结构留在世界中 |
| `FAILED` | `16` | 格式、世界边界或不可恢复提交错误，需要玩家处理 |

蓝图内部以一份规范化结构快照为准，结构磁盘最终仍使用原版结构 NBT 能表达的内容，不发明另一套只能由悦灵读取的世界结构格式。规范数据包含尺寸、调色板、方块位置与 `BlockState`、方块实体 NBT、实体条目、锚点、旋转和镜像；不包含方块或流体计划刻队列，也不保存计划刻剩余时间。

导入层采用适配器，导入后统一转换为上述规范快照：

| 来源 | 兼容要求 |
| --- | --- |
| 原版结构 `.nbt` | 完整读取 `size`、`palette/palettes`、`blocks`、方块实体 NBT 和 `entities`，作为基准格式 |
| Create 蓝图/结构 `.nbt` | 识别其基于原版结构的字段和 Create 附加元数据；可表达内容归一化为原版结构语义，不依赖 Create 的蓝图加农炮运行时代码 |
| Litematica `.litematic` | 读取压缩 NBT、多区域偏移、区域调色板、压缩方块状态数组、方块实体和实体；按确定顺序合并多区域并保留负偏移 |

导入器必须显式报告未知方块、缺失模组、损坏调色板、区域重叠冲突和无法映射的扩展字段，不能静默变成空气。Litematica 或 Create 中超出原版结构语义的信息只可给出警告或拒绝导入，不能假装已经复原。旧 `DataVersion` 通过当前版本的数据修复边界升级；当前项目不因此承诺 Plasticraft 旧存档兼容。

限制数值：单轴尺寸至多 512 格，方块条目至多 2,097,152 个（Litematica 按区域并集体积计），实体条目至多 4,096 个，上传文件至多 8 MiB。存有塑料成型舱蓝图的磁盘不能兼作施工蓝图。

现有 AnvilCraft 结构保存流程若仍省略方块实体 NBT 或固定写出空 `entities`，必须先补齐到完整原版结构语义，否则“内容物和实体复原”没有可靠输入。该工作属于建设系统前置条件，本体扫描器已补齐。

## 3. 流体封堵、真实拆除、掉落物回收与提交

每个活动任务严格按“权限预检 -> 流体封堵 -> 真实拆除 -> 可选掉落物回收 -> 投影建造”推进。蓝图声明区域内进入拆除集合的原有非空气方块都需要先拆后建，即使原状态已经与蓝图目标完全一致也不复用；空白格是否进入该集合由协调室清场策略决定。Litematica 多区域之间未声明的空隙不扫描。全部可执行拆除完成、永久障碍及按配置保留的障碍已经记入跳过集合后，才允许派发第一个建造操作。拆除阶段不能一边清外墙一边让建设悦灵进入内部放置最终施工投影，避免真实世界变化与假碰撞交错后无法判断可达性。

流体不能通过逐格设为空气处理。无限水源、相邻源方块或外部流入可能立刻补回已经清除的位置，因此任务只洪泛扫描蓝图声明区域内的流体，并允许在区域外一格建立临时封堵壳来切断外部流入；绝不继续追踪壳外海洋。含水固体不替换。内部全部流体格与必要边界壳形成一个有限批次，由建设悦灵从玩家或任务休息室取得真实填充材料；区内填充严格按世界 Y 从最低未完成层向上派发，最低层存在租约、等待项或未交付项时不得领取更高层。整批填满并切断再生和回流后，拆除悦灵才开始拆除区内填充块。

临时填充只选择能够稳定占据流体格、没有方块实体、不会下落或立即自毁的普通实心方块。材料规划先保留完整蓝图本身所需数量，再从剩余候选中选择库存最多的一种。填充块是真实消耗、真实放置并写入任务台账的世界方块，不是假放置或最终施工投影。

区内填充块在拆除阶段打成掉落物，可以由收集悦灵回收并再次用于后续封堵或建造。区外一格壳（`shell=true`）在拆除阶段不派发，留到安静提交写出真实方块后再砸掉，避免水在施工投影里回流。取消时已经真实放置但还未拆掉的任务填充块原样留在世界。

拆除悦灵遵循以下规则：

1. 只执行拆除操作，不从玩家或休息室取料，也没有携带物或返还物
2. 切石机到目标的触及距离为 `1` 格，必须存在无阻挡的接近位；到位后先转向再瞬间破坏，不显示原版挖掘裂纹或累计进度
3. 破坏语义严格对齐 AnvilCraft 普通铁砧砸中“下方有切石机的方块”路径，而不是玩家挖掘或普通 `destroyBlock`：先拒绝负硬度状态，再使用本体 `BlockMiningEffect.NORMAL` 和 `BreakBlockUtil` 创建正确虚拟工具、结算经验与方块掉落、执行方块的 `spawnAfterBreak` 及多方块移除回调，最后把目标更新为空气。实现时复用本体公开服务或把相同公开 API 组合封装在独立适配器中，避免再维护另一套战利品算法。爆炸抗性 ≥ 1200 只伤铁砧，悦灵忽略，黑曜石可拆
4. 拆除是真实世界破坏，目标状态立即消失并正常触发相应世界变化；产生的物品、经验和容器内容物全部生成在原位置，拆除悦灵不会吸取。工人不扣 FE
5. 基岩、命令方块、屏障等生存模式无法正常破坏的状态标记为永久障碍；它们不阻塞整个拆除阶段，但对应位置的建造操作自动跳过，最终提交也不得覆盖
6. 任务所有者没有权限破坏或放置的受保护位置不属于永久障碍，也不允许自动跳过。规划阶段或执行前发现权限拒绝时，整个任务进入 `WAITING_PERMISSION`；权限恢复后从原台账继续，玩家也可以取消任务
7. 拆除路径按从外向内的可达表面逐层剥离。每次删除真实碰撞后重算局部可达空间；拆除悦灵可以进入已经清空、未来建造阶段才会使用的蓝图格，未来 PLACE/SEAL 预约和建造防自封约束不得把这些格子当成拆除障碍。多只拆除悦灵通过目标租约避免重复破坏同一格
8. AnvilCraft 大型方块和其他多方块结构使用拆除适配器识别核心及附属 `part`，只执行一次符合该结构正常破坏语义的核心拆除，不能逐个部件重复产生掉落
9. 拆除不得把该格写成已交付实心投影；未交付格子仍是蓝图目标的半透明预览
10. 蓝图声明范围内哪些格允许拆除由协调室的空白格清场策略决定：默认 `CLEAR_AREA` 拆除整片声明区域，`KEEP_BLANK` 只拆与蓝图实际放置方块重合的格。判断在折核心之前按声明格进行，因此半扇门不会被留下；封堵填充块是施工自己放下的方块，两种策略都无条件清走。策略同时存于协调室和任务进度：未认领或未规划任务在下一次规划时读取当前设置，已认领且已规划任务切换按钮会立即同步未完成拆除台账；`CLEAR_AREA` 补入显式蓝图空白格的 `DEMOLISH`，`KEEP_BLANK` 将这些未完成操作标为 `SKIPPED`，再切回时只恢复世界中仍存在真实方块的未完成空白格，已完成拆除不恢复

扫描结果中存在正常可拆方块、但任务没有可用拆除悦灵时，才执行暂停/跳过配置。选择“暂停”时进入 `WAITING_DEMOLITION`，报告需要拆除的位置并让其他任务悦灵悬停；选择“跳过”时把这些障碍保留在世界中，并将对应建造位置记为跳过。基岩等已经确认无法拆除的永久障碍不读取这一配置，也不会使任务停在拆除阶段；其他可拆位置处理完后直接进入建造阶段。任何被保留障碍占据的目标位置都直接跳过，障碍造成的封路还可能使其后方目标因不可达而跳过，任务最终得到 `COMPLETED_INCOMPLETE`。权限拒绝是例外：无论配置为何都必须暂停，不能借缺工种“跳过”间接绕过保护。没有绑定休息室的世界悦灵固定暂停。

拆除产生的每个 `ItemEntity` 都由任务台账关联任务 UUID、来源操作和数量；任务标记必须参与物品实体合并判定，避免任务掉落物与玩家原有掉落物合并后无法区分。没有可用收集悦灵时，任务不等待回收，全部掉落物继续留在原位置并照常进入建造。有可用收集悦灵时，中央调度器在拆除进行期间即可分配掉落物租约；全部拆除结束后进入一次有界的 `COLLECTING_DEBRIS`，让仍可装载且能够卸货的悦灵收取本任务掉落物。九格满载的悦灵先去卸货：能塞进所有者背包或休息室下方容器的先插入，两边都塞不下的扔在该目标旁边地上，腾空后再决定是否继续收。未领取的剩余掉落物留在世界，随后进入建造。已经被玩家、漏斗或其他实体拿走、烧毁或自然消失的掉落物从台账标记为外部结算，不复制补发。

收集分两种载体：

- 空手通用工：必须飞到工具触及范围内才捡起 1 个，没有九格背包。捡到后飞回所有者塞进玩家背包，或飞回休息室塞进下方容器；目标库存已满时把塞不下的扔在所有者或休息室旁边地上，然后继续
- 磁铁收集：九格只是吸入时的临时库存，正常遵守物品最大堆叠数，不是长期背包。自由模式每次吸入后以当前位置重扫当前 `16` 格任意 `ItemEntity`，一次动作吸入范围内可装下的掉落物；不收经验球，磁铁不消耗原版耐久。九格装满后停止吸入并立刻去卸货。卸货时必须尽力腾空：先插入所有者背包或休息室下方容器，玩家和休息室都塞不下的也要扔在该目标旁边地上，不能把物品留在身上等下一次

一次任务领取只锁定本任务生成的可拾取掉落物，不收取附近无关物品。卸货目标：无休息室飞回所有者背包，已绑定休息室则飞回休息室并插入下方容器。空手单件和磁铁九格都要尽力腾空；目标库存已满时把塞不下的扔在该目标旁边地上，然后继续，不能把收集物留在身上。卸货或丢地都不阻塞其他工种继续任务。收完或腾空离场后先飞离蓝图范围再交还给原版游荡，不在即将被建造占用的格子里停着。

采用施工投影可以消除最困难且收益很低的两类问题：建设悦灵不需要理解沙子支撑、红石粉附着、活塞更新、锁存器拓扑或模组机器的逐块初始化顺序；真正的目标方块只在所有材料交付完成或玩家取消任务时进入世界。不过，用户看到的“假方块”必须提供对应碰撞，所以建造阶段的空间装配顺序仍然需要规划。

施工过程区分两层投影：

- 未交付投影只负责预览，没有碰撞，悦灵可以穿过它抵达结构内部
- 悦灵完成一次方块交付后，该位置变为“已施工假方块”，显示目标方块模型并提供目标 `BlockState` 对应的 `VoxelShape` 碰撞

假方块不应真的把世界位置替换成成千上万个占位方块或方块实体。使用按区块段保存的 `ConstructionProjectionIndex`：服务端记录已交付位置和目标状态，同一 tick 的交付与邻接变化只把区块段标脏，tick 末每段最多同步一次完整快照；世界碰撞查询从同一索引追加虚拟 `VoxelShape`。仓库已有为动态塑料制品扩展 `BlockCollisions` 的窄接口，实现时应复用这一索引边界，避免再放置每格一个方块实体。

当前 1.21.1 客户端由 `BlueprintProjectionRenderer` 编排三个阶段：`AFTER_BLOCK_ENTITIES` 绘制已交付方块实体，`AFTER_TRANSLUCENT_BLOCKS` 绘制已交付流体，`AFTER_ENTITIES` 绘制已交付 MODEL、未交付全息、实体投影和边界。`BlueprintProjectionSectionRenderer` 在工作线程按 `16³` 区块段烘焙方块模型与流体，保留模型声明的原始 `RenderType`；已交付 MODEL 直接写主目标，全息颜色写入独立投影目标。`BlueprintProjectionTarget1211` 只封装 1.21.1 的离屏目标、主深度复制和预乘 Alpha 合成，是未来版本替换的显式边界。经典半透明层在相机移动超过 `2` 格后重排。

分区渲染同时限制为最多 `8` 个场景、约 `256 MiB` GPU 网格、`16` 个未完成任务、每帧 `4` 个区段编译、`2` 次上传与 `8 MiB` 上传量。投影准备缓存最多 `8` 份，每帧总计处理 `8192` 个条目且每场景最多 `2048` 个。客户端蓝图快照下载逐块校验，残缺下载 `200 gt` 超时、`20 gt` 后可重试；单个低优先级守护线程最多排队 `2` 份解码，LRU 最多缓存 `8` 份或估算 `256 MiB`，解析在客户端线程外完成后再原子发布。覆盖视图 LRU 最多 `8` 份或 `4,194,304` 个方块，并在任务变换或快照淘汰时失效。资源重载清空上述投影缓存、网格与离屏目标。活动施工边界使用黄黑交替警戒环和向上短距离淡出的区域提示，未启动投影仍使用青色边界。

服务端把已交付区段推给客户端时按可见区域调度：同一 tick 的交付只把 `(job, section)` 标脏，tick 末每维度最多下发 `16` 个区段，按到最近玩家的水平距离升序取，超出预算的区段留在队列里下一刻继续；当前没有任何玩家能看到的区段直接从队列丢弃，玩家开始追踪该区块时由区块发送事件补一份完整快照。区段载荷按段内局部调色板加稀疏位集编码：状态先去重成段内调色板再按索引引用，位置在条目数 `< 256` 时逐条写 `12` 位局部坐标、否则改用固定 `512` 字节的 `4096` 位位集。解码端把条目数、调色板长度和掩码数一律夹到单段 `4096` 格上限，位置与状态数量不一致时整段作废，损坏或伪造的载荷不得先按声明分配再校验。

这一虚拟占位层具有以下硬规则：

1. 玩家、悦灵、其他普通实体和塑料实体都与假方块碰撞，服务端是权威，客户端同步同一形状以避免走动回弹
2. 碰撞只表示目标状态的几何；假方块不提供红石信号，不接收随机刻或计划刻，不流动，不创建目标方块实体，不执行 `onPlace`、`neighborChanged`、生存检查或模组机器逻辑
3. 栅栏、墙、门、活板门等依赖相邻状态的形状通过只读“蓝图覆盖视图”计算：已交付位置读取目标状态，其他位置按规划所需读取目标或真实世界状态，不能因为世界里仍是空气而得到错误形状
4. 目标状态本来没有碰撞时，假方块也没有碰撞；例如红石粉、铁轨、草、开启的栅栏门、花和多数流体只显示施工投影
5. 新增一块虚拟碰撞前先检查其形状是否与玩家或实体相交。被占据时该操作等待并报告“施工位置被占用”，不能直接把实体封进形状中。占用检测忽略施工悦灵、掉落物和经验球
6. 路径检测只查询“真实世界碰撞 + 已交付假方块碰撞”，因此会绕过刚完成的假墙、台阶和关闭门体，也会穿过铁轨、草和开启栅栏门等空碰撞状态；交通预约只排斥最终工作位或时隙，不得作为路径碰撞
7. 已交付木头等实心方块看起来就是世界上的不透明方块，不是绿色半透明幽灵；世界格仍是空气，Jade 显示「空气」是预期
8. `writesProjection()` 只有 `PLACE` / `ATTACHED` 为真；`CONTENT` / `FLUID` / `ENTITY` / `DECORATE` 的 `DELIVERED` 表示材料已扣、提交时再写入。`DECORATE` 只更新父方块已有投影的未加工掩码，不自己占格。拆除不得往投影索引里写格子

施工顺序不再分析红石或方块支撑，但必须解决“先封外墙后无法进入内部”的几何装配问题。规划器从完整目标碰撞集合做一次反向可拆解分析：从蓝图外部可达空间开始，反复选择能够在工具触及范围内从外部接近、移除后仍连通的目标块，记录拆解顺序；正向施工使用它的逆序，就会先完成内部、最后从外侧封口。每次真正派发前还要验证放置后的撤离路线，不能只保证够得到目标，却把执行悦灵封在内部。候选放置后的局部闭腔洪泛预算为 `8192`，超出预算按不安全处理；完整外部空间按布局版本缓存，候选闭腔按封闭版本与服务器 tick 复用。两个碰撞封口互相成为闭腔内最后工作时，按 `order/id` 只放行唯一领头操作，另一个在领头租约交付后再复核，不能让双方永久互等。别的悦灵已租的封口只在它压住同一腔体的边界时才要求串行，同样按 `order/id` 由较前者当选主封者；无碰撞形状的方块（铁轨、红石粉等）封不住腔体，不参与串行——否则任务另一头任意一份墙体租约都会让这里永远拒绝施工。防自封落地挂在现有 `ConstructionAssembler` / `chooseApproach` / `tryDeliver` 上；TODO 12 的算法对照笔记 `docs/construction-anti-enclosure.zh_cn.md` 已随实现删除，不要另起一套作业补丁。

拓扑安全是硬约束；在当前所有安全候选中再使用原先的偏好排序：先低层后高层，同层优先远离主要入口/取料方向的位置，再逐渐靠近。真正派发时只在队首同层的前 `24` 个待办候选内按离该悦灵的距离重排，让成环或成排结构转着圈就近施工，而不是沿固定扫描方向放一块就飞到对面再飞回来；同层候选之间不存在支撑先后，拓扑安全仍由每个候选各自的接近位、闭腔与撤离复核把关。跨层不重排，仍先铺下层再压上层。批量取料只预留材料，不把整批未来方块提前标成即将成墙；悦灵每交付一格后重新计算安全接近位与封闭腔。批内没有安全同材目标时截断批次并返还余料，让内部或其他材料先施工。多个悦灵只从同一安全前沿领取不同目标，并预约目标接近位和撤离段。世界被玩家临时改动后只重算受影响区块段和局部路线，不重新扫描整个蓝图。

建造、等待材料、等待拆除、拆除和收集阶段持续监听服务端真实方块写入。蓝图显式声明格出现与目标 `BlockState` 不同的新方块时，任务立即停止建设派发，在受影响位置追加反应式 `DEMOLISH` 操作，由切石机工种按普通拆除路径处理；掉落沿任务标记、台账和收集悦灵流程结算。`CLEAR_AREA` 会连显式空白格一并处理，`KEEP_BLANK` 保留显式 `AIR` 格的新方块，但实体目标格仍会处理。与目标状态完全相同的外部方块可直接满足 `PLACE` / `ATTACHED`，移除对应投影并返还尚未提交的在途或已交付材料；若冲突覆盖已交付的实体、内容或流体投影，也必须撤销投影并重置对应子操作。未声明的稀疏空隙不属于清场范围；永久障碍沿既有跳过规则记为残缺。`COMMITTING` 阶段继续遵守强制提交规则，提交前的新变化可被最终发布覆盖。

`writesProjection()==false` 的 `ENTITY` / `FLUID` 在六向都被未交付方块占住时，允许悦灵进入目标格交付；已交付假碰撞目标仍禁止插在格子里执行。已交付塑料实体投影施工期只显示，提交后才生成硬碰撞，避免把玩家卡进工地。

全部非跳过建造操作交付后进入完整提交。通用流程如下：

1. 冻结任务派发，确认所有相关区块已加载、材料托管台账闭合、投影索引和蓝图哈希一致
2. 锁定目标区域的施工交互，建立可在异常重启后续做的提交日志
3. 直接写入目标方块状态，内部不发送普通邻居更新、不触发掉落，也不逐块调用玩家放置逻辑
4. 在方块状态齐全后载入方块实体 NBT，再交给大型多方块适配器恢复核心与部件关系
5. 写入流体状态和必要的后续流体刻；实体在方块与方块实体完成后统一生成
6. 移除施工投影碰撞和渲染，向客户端发布完成状态，最后只对结构边界和明确要求的适配器执行受控更新；BOUNDARY/PUBLISH 再写一遍蓝图状态后 `restoreWirePorts`
7. 释放区域锁和观察覆盖租约，提交材料消耗与返还台账；观察悦灵按返航、待机及第 6 节资格继续或停止自身区块票，任务不能越过观察加载服务直接删除票
8. 提交结束后砸掉仍留在世界的区外封堵壳

完整提交只写入已经通过拆除阶段且没有被跳过的目标位置。进入 `BUILDING` / `WAITING_MATERIAL` / `WAITING_DEMOLITION` / `DEMOLISHING` / `COLLECTING_DEBRIS` 后，蓝图显式声明格出现与目标不符的新真实方块会先转成反应式 `DEMOLISH`，不能被提交阶段静默覆盖；与目标完全相同的外部方块则按运行时复核直接满足对应操作并返还未提交材料。`COMMITTING` 已冻结派发后仍按强制发布语义覆盖提交前最后一刻的普通变化。不可生存破坏或按配置跳过的原有障碍永远保留，对应建造操作不得在提交阶段偷偷覆盖。权限拒绝尚未解除时任务根本不能进入完整提交；若提交前权限发生变化，则回到 `WAITING_PERMISSION`。已交付目标的虚拟碰撞在提交前已经阻止玩家和实体进入最终实体碰撞形状；无碰撞目标即使与实体重叠也按原版相应状态处理。

玩家主动取消施工不是回滚，而是一次“按当前进度提交”：

1. 立即停止新的流体填充、真实拆除、掉落物租约和建造取料；已经真实拆除的方块保持被拆除，原地掉落物与收集悦灵已经取得的库存保持真实状态
2. 已经完成交付并显示为假方块、假流体或实体投影的操作，按与完整提交相同的安静写入流程变成真实内容
3. 建设悦灵尚未到达目标的在途资源不计入进度，立即转向来源玩家或任务休息室返还，不再完成当前交付；返还后无休息室悦灵交还给原版游荡、休息室悦灵依次回库，尚未取出的资源不发生变化
4. 未交付、被跳过或仍被不可拆障碍占据的位置保持取消瞬间的真实世界状态；若某个已交付投影在取消时已失去写入权限，则不得借部分提交覆盖，而应移除该投影并返还对应托管材料
5. 清除剩余投影和任务租约，结束观察覆盖调度，任务结束为 `STOPPED_PARTIAL`，不再自动恢复或继续

取消发生在流体封堵或拆除填充块期间时也立即停止，不启动任何额外清理。已经真实放置但还未拆掉的任务填充块原样留在世界；未放置的在途填充材料按普通在途资源立即返还。任务只移除虚拟投影和租约，不能静默删除、无掉落清除或继续拆除这些真实填充块。

因此，一个目标为 `3 x 3 x 3` 圆石的任务在拆除原有石头并完成前两层 `18` 块投影后取消，会立刻得到两层真实圆石；第三层保持空气，已拆石头不会复原。部分提交不保证红石机器可用，也不为玩家主动取消造成的半结构做自动修复。若取消请求到达时任务已进入不可分割的发布点，则先完成正在发布的事务，再以实际已发布进度结束，不能把同一批提交一半回滚。

通用方块不使用假玩家放置。假玩家会触发物品 `useOn`、邻居更新、成就/事件和模组方块初始化，反而破坏保存的红石与机器状态。只有某种方块或实体无法通过公开结构载入接口正确初始化时，才由独立 `PlacementAdapter` 在受控阶段使用 AnvilCraft 假玩家；适配器必须声明消耗、返还、附加位置和更新范围，不能让假玩家成为所有方块的默认路径。

提交保留原版 NBT 中已经存在的红石粉外观与功率、比较器/中继器朝向与锁定、拉杆/按钮状态、稳定的活塞伸出/收回状态以及方块实体配置。铁砧工艺红石导线另把蓝图四向写入本体端口覆盖表，强制保留已连接端口，强制隐藏未连接端口，之后网络更新也不会按邻居补臂或把平行线连成一片。结构内部不做一轮无差别邻居更新，因此不会在施工中启动或拆坏机器。提交完成后世界恢复正常规则；功率可随外部供电变化，连接方向保持蓝图。

原版结构 NBT 不包含计划刻队列，因此不承诺恢复中继器“还剩几刻触发”、流体“还剩几刻流动”或计时器的相位。稳定伸出/收回的活塞可以复原；正在运动中的活塞、移动方块实体和半个游戏刻的瞬态不能在只使用原版结构 NBT 的前提下精确续播。验收目标是机器在相同外部环境中从保存的稳定状态恢复并继续正确工作，而不是恢复服务器保存瞬间的调度队列。

“原子提交”定义为玩家和机器观察不到可运行的半成品，不强制任意巨型 Litematica 结构必须在单个服务器 tick 内完成所有内存写入。普通结构可以单 tick 写完；超大结构应在区域锁和完整施工投影遮蔽下分区写入，期间不运行结构内部逻辑，全部写完后在一个发布点移除投影并启用真实结构。这样视觉和玩法上仍是瞬间完成，同时避免单次提交超过服务端 watchdog。

Create 的 SchematicPrinter 和 BlockHelper.placeSchematicBlock 可参考其结构遍历、易碎方块延后和客户端更新标记，但 Create 蓝图加农炮本身仍是逐块真实放置，也不理解红石依赖，不能直接承担上述安静提交。

## 4. 材料、内容物、流体、实体与多方块

蓝图解析后先生成规范施工操作，而不是简单地认为“每个非空气方块消耗一个同名物品”。操作适配器负责把目标快照映射为所需物品/流体、交付表现、最终写入和返还物：

- 普通方块通常消耗其放置物品，朝向、含水、点亮、功率等状态属性由蓝图恢复，不额外消耗物品
- 临时流体填充块同样必须从真实来源取出，真实放置后再由拆除打成掉落物；被收集并成功卸载的填充材料可以重新参与后续封堵或建造，台账必须防止同一物品在“已放置”和“已回收”状态同时存在
- 门的上半、床的另一半、活塞头和大型机器部件是依附操作，不能重复消耗和重复放置。成对大箱子以 RIGHT 为核心一次扣两只箱子，LEFT 为依附格；规划里没有成对另一半的落单 LEFT/RIGHT 仍按单箱处理，提交或取消时收成 `SINGLE`，不得把半个大箱子写进世界
- 没有常规物品形态的状态必须由专用适配器映射；无法映射时明确列为“不支持的材料操作”，不得免费生成
- 一只悦灵一次只抓取一个 `ItemStack` 或一个流体容器；箱内多组内容、机器输入和实体装备可以形成多次交付到同一目标的子操作

内容物必须真实取料，不能把蓝图 NBT 中的物品和流体直接复制进世界。方块实体的容器物品、储罐流体，及有库存实体的内容和装备都进入材料清单。能力库存拆成 CONTENT 操作后，必须从配置 NBT 中删除已经被抽取的序列化 `SlotItem`，避免最终载入配置再插槽时复制同一内容。普通配置 NBT、名称和不代表资源的机器设置可由蓝图恢复，但仍需经过类型和权限校验。

告示牌与悬挂告示牌不算“不代表资源的配置”，必须按同一条约束拆成二次加工，不允许随方块一次带字放下：

- 规划阶段由 `SignDecorationAdapter` 从配置 NBT 中删除 `front_text` / `back_text` / `is_waxed`，每一项拆成一条 `DECORATE` 子操作挂在该 `PLACE` 下；一条操作只携带一种材料，所以正反面与书写、染色、发光、打蜡各占一条，靠 `slot` 编码区分
- 拆分时必须把每一行压平成 `Component.literal(getString())`，只留可见字符，样式、悬浮与点击事件全部丢掉。蓝图来源不可信，而原版 `SignBlockEntity` 执行牌面 `run_command` 用的是权限等级 2 的命令源，足够跑 `/gamemode`：不压平就等于允许玩家用蓝图造一块牌子、点一下把自己切成创造。压平在抽取期一次做完，因为提交期只有 `writeBlockEntities` 会把配置 `loadWithComponents` 进真方块，PASTE 阶段只写方块状态，抽取是唯一必经的收口点
- 消耗与玩家手动加工一致：书写文字免费，染色消耗对应染料，发光消耗荧光墨囊，打蜡消耗蜂巢；每一面各算一次，不共用同一份材料。这些状态没有其它常规物品形态，因此按“不得免费生成”走专用适配器而不是列为不支持
- 交付出来的假告示牌一开始必须是空白的：`DECORATE` 完成前不显示文字、颜色和发光，之后随每条子操作交付逐项显示。服务端把该位置还没做完的加工位掩码放进投影索引，随区段差量下发，客户端渲染前按掩码裁剪蓝图快照 NBT
- 只有 `DELIVERED` 才清掉掩码位。缺料或不可达被跳过的加工项永远不会写进最终方块实体，假方块也必须一直空着，不能预告一个提交后并不存在的效果
- 提交时由已交付的 `DECORATE` 子操作合成最终方块实体 NBT，未交付项保持原版空白默认；解析不出来的 `SignText` 拆不成加工项，原样留在配置里，不悄悄丢掉蓝图数据。留下来也不会绕过压平：原版 `loadAdditional` 用同一个 codec 解析，一样失败并回落空白牌面。解析成功的一面无论有没有可见文字都会从配置里删掉，所以“只有点击事件、没有字”的一面也不可能被复原
- 未交付的施工全息投影仍显示带字的目标外观，那是目标预览，不是已交付结果；只有已交付假方块从空白开始

所有取出的资源先进入任务托管台账，记录来源玩家或来源容器、原始槽位/流体接口、数量、执行悦灵、目标操作和可能的容器返还。悦灵携带的是托管资源的实体表现。取消任务时，已经交付的资源随部分提交消耗，尚在途或只完成预约的资源按台账返还；休息室失效或提交失败也只返还尚未发布的资源，不能把已经变成真实世界内容的物品再复制一份。

未认领时创造模式所有者不扣背包，按蓝图需要直接给出材料；生存模式从主物品栏和副手按匹配规则扣除。认领后即使创造模式玩家也不能绕过下方容器。下方若是创造板条箱，则按创造模式无限给出蓝图所需物品，不消耗箱内过滤物。

流体方块由悦灵取得装满对应流体的桶或注册的兼容流体容器，在工具触及范围内完成投影交付。空桶等容器返还只有在资源转换确认后才结算；交付前取消时恢复原来的装液容器，交付后取消时流体进入部分提交并结算空容器。非整桶的储罐内容按流体能力精确抽取并托管，若来源接口或目标适配器不能表达该数量则暂停并报告，不能四舍五入。

AnvilCraft 大型方块在解析阶段识别核心控制器和全部 `part`：

- 整座多方块折叠成一个以核心位置为锚点的逻辑操作，只消耗核心控制器所代表的正确物品
- 蓝图中的其他 `part` 只用于校验范围、方向、投影和碰撞，不生成重复取料任务
- 核心交付时一次激活整组施工投影碰撞，前提是整组形状均未占据且悦灵有撤离路线
- 最终提交由对应适配器先恢复核心数据，再建立部件；不能逐格伪造多个互不关联的控制器

实体使用 `EntityBuildAdapter` 注册表处理“快照类型 -> 可接受物品 -> 投影交付 -> 最终生成 -> 返还物”。目标是支持所有有稳定世界语义、能够由物品表达的持久实体，并明确排除玩家、掉落物、经验球、闪电、投射物、区域效果云以及其他纯瞬态实体。

具体规则如下：

- 船消耗对应木种和类型的船物品；矿车、盔甲架、画、物品展示框等使用各自物品适配器。矿车目标必须等待下方铁轨完成交付；反过来交付铁轨时忽略目标格内的矿车占用，使既有漏斗矿车不会阻止轨道施工
- 生物可以消耗匹配类型的刷怪蛋，或消耗保存了该类生物的高粘性树脂块
- Plasticraft 塑料实体消耗能够重新放出该实体的塑料制品物品，完整保留玩家模型、材料、颜色、方向和真实内容物；施工阶段只显示静态实体投影，最终提交时再生成具有硬碰撞的塑料实体
- 生物只要求实体类型一致，不要求血量、仇恨、药水效果、AI 记忆等完整运行 NBT 一致；位置、朝向和结构所需的基础姿态仍按蓝图生成
- 有库存、装备或容器内容的实体，其内容仍必须单独真实取料并在生成后装入，不能因为“类型一致”而复制内容
- 树脂块/高粘块交付后在目标位置显示无 AI 的实体施工投影，并按现有规则生成 `1-3` 个树脂返还物；悦灵先把返还物送回任务休息室下方库存或来源玩家，再领取下一项。真实生物只在最终提交时生成
- 树脂铁砧带 `SAVED_ENTITY` 也是捕获物，但整砧消耗不返还树脂
- 模组实体没有刷怪蛋或标准物品时，以能够保存对应类型的树脂捕获物作为生物类兜底；非生物实体仍必须注册明确适配器

缺料/缺工种策略为“暂停”时，休息室悦灵依次返回并入库；无休息室悦灵在蓝图范围外交还给原版游荡或就地悬停等待。策略为“跳过”时，缺失建造材料、临时填充材料或拆除能力对应的操作记入跳过集合，其他可执行操作继续，最后自动提交 `COMPLETED_INCOMPLETE`。收集悦灵是可选回收能力，缺少它不会触发暂停或跳过；观察悦灵是否缺失按第 6 节的区块可用性处理。不可拆永久障碍及其目标位置始终直接跳过，不受该策略控制；权限拒绝则始终暂停。系统只保证完整、未跳过任务的红石和机器复原；选择跳过导致的结构失效属于玩家决定。

`ConstructionWaitReason.ENERGY` 枚举位保留，避免后续序号漂移，界面不展示。工人无能量资格，不要再写报价或 `ENERGY` 拒派。

首次进入缺料、来源不可用或路径阻塞状态时向任务所有者报告一次，之后在休息室 GUI 中持续显示原因、缺失材料和受阻目标；状态未变化时不重复刷屏。施工悦灵本身不再有设置界面。

“来源不可用”与“来源里没有某件物品”不同。玩家离线/跨维度、休息室下方容器或能力整体消失等情况属于来源不可用；相关悦灵立即停止世界交互，悬停并保留任务租约和携带物，不再寻找新活。任务台账继续保留悦灵、租约、携带物和原来源关系，不能因实体所在区块暂时卸载而重新派发同一资源。来源恢复后，调度器先确认或重建悦灵位置、来源和后续路线所需的加载覆盖，再唤醒悦灵继续。真正检查到库存中缺少材料时才执行暂停或跳过策略。普通返还物、空手收集单件和磁铁九格临时库存都一样：目标仍存在但库存已满不进入等待，把塞不下的扔在休息室或玩家旁边的地面，然后继续任务。九格不是长期背包，卸货时必须腾空。

## 5. 悦灵休息室、物流与调度

悦灵休息室是托管与任务入口方块，不是无人机站。站内最多托管 16 条 `AllayWorkRecord`，另有 `1` 个任务结构磁盘槽，共 1 个实际物品槽，不设置工人物品槽、电容器槽、材料库存槽或内部 FE。下表面是唯一物流接口面；下方容器暴露的物品库存和流体能力就是已认领任务休息室可使用的材料来源。

休息室没有合成配方，本轮不擅自发明。

四个水平侧面只显示已从下方库存原子预约、即将被建设悦灵取走的物品；预约物保存在任务托管台账中，不借“渲染槽”制造隐藏库存。普通返还物先经下方接口插回容器；容器存在但已满时，返还物直接作为掉落物生成在休息室旁边。拆除和观察悦灵不使用取料通道；收集悦灵使用独立卸载预约。

悦灵只从顶部入库或出库。顶部泊位是单通道状态机：入库和出库不能同时发生，每 `20 gt` 最多处理一只。入库悦灵对准后服务端把完整 `AllayWorkRecord` 原子转入托管列表并移除实体；通道仍占用 `20 gt`。出库先从托管记录原子转出，在释放点生成真实实体。休息室本体始终使用稳定方块碰撞，不为舱门临时打开可供玩家或其他实体进入的洞口。

召回扫描休息室周围 `16` 格，只登记属于发出命令玩家且剩余托管容量能够接纳的悦灵。手动召回与自动返室都按登记瞬间到顶部中心的距离稳定插入队列，距离相同按 UUID；登记后不再按实时距离重排。顶部中心只留给当前队首；其余等待者在室顶上方 `3` 格、半径 `3` 格的四边环上按 `1.2` 格间距悬停。每只悦灵入队时取得固定槽位，到达中心或等待槽位后必须清除旧飞行任务、路点和过境预约；队首入库后只有下一只移向中心，其余等待者不随队列推进整体换位。每层 16 个槽位用完后向上 `1` 格叠层。满员拒绝覆盖已有记录，已经等待的悦灵保持原槽位。

休息室不接入电网、不请求功率，召回、出库与入库不依赖供电。不要给休息室加 `IPowerConsumer`、`POWERED` 或内部电量。

施工悦灵自身不消耗 FE，也不向电网请求功率。不要给悦灵加内部电量、电容器容量、空中 gt 计费、距离费、瞬时操作费或任务报价。不要用 FE 作为观察加载资格。

当前只实现单休息室的本地认领、20 gt 顶部通道和稳定等待队列。远程转运模式由 TODO 14 在这套现有通道上扩展：两个同维度的相邻调度节点每段最多相距 `128` 格，多个休息室可以组成多跳转运图，使远处室内悦灵沿休息室链路来到任务休息室；普通网络不支持跨维度调度。远程悦灵只在预计能缩短任务完工时间时调度。借调与任务休息室本室出库同刻推进：任务休息室不必先把本室悦灵全部放完才开始抽调远室，凡按预计完工时间仍有收益的源室本轮都各出库一只，节流只靠每个休息室自己的 `20 gt` 顶部通道，因此多室是各自 `1 s` 一只并行起飞，而不是按到任务休息室的距离串成一条队。每个施工任务最多同时有 `64` 只四类悦灵处于参与状态；其余留室或继续处理其他玩家的任务。被借调悦灵完成任务、清空任务携带物或收集库存后，沿调度链返回原休息室，不永久留在任务休息室。

被借调的悦灵在任务休息室是**客工**：它只把任务休息室当作取放材料的接口，不入库、不排队、不占用任务休息室的顶部 `20 gt` 通道与托管容量。中途每一跳的转运节点仍按普通入库/出库处理，只有抵达任务休息室的最后一跳改为挂靠。因此任务休息室的通道和托管位始终只服务本室悦灵，外来悦灵不会把本室悦灵堵在队列里；客工在任务休息室无活可做时立刻沿链返程，而不是滞留待命。任何原因滞留在别室托管栈里的外来记录（例如玩家召回）都尽快转发回原休息室，不因该室正在协调任务而留用。

无休息室建设、拆除和观察悦灵只响应到该蓝图任意当前可执行目标的最近直线距离不超过 `128` 格、且确实存在可飞路径的活动蓝图；距离不以蓝图锚点或整个包围盒中心计算。无休息室建设悦灵先飞到任务所有者玩家一格范围内取料，再飞到目标交付；无休息室拆除悦灵不需要取料，直接飞向被分配的拆除目标；无休息室观察悦灵领取任务区块覆盖路线。任务休息室同样不能把单次施工目标分配到自身 `128` 格发现范围之外；远程休息室只能通过每段不超过 `128` 格的转运把悦灵送到任务休息室。若某蓝图已由休息室认领，这三类无休息室悦灵完全退出该任务。它们都不得停留在已放置蓝图的包围盒内；放置新蓝图时，范围内的无休息室悦灵即使蓝图尚未启动也会主动撤离。

无休息室收集悦灵不自动参加已被休息室认领的蓝图中央任务，而是持续扫描自身当前位置 `16` 格范围内可拾取的 `ItemEntity`。每收起一批掉落物后，以新的当前位置重新扫描当前 `16` 格，因此可以沿连续掉落物链逐步移动，但不会先对更远区域做全局搜索。它不吸收经验球。没有可拾取目标时交还给原版游荡；九格库存装满后必须停止吸入。无休息室时优先向悦灵所有者背包卸货；所有者不在当前维度时可向当前在线同队成员卸货，未安装 FTB Teams 时仍仅限所有者。已绑定休息室时向休息室下方容器卸货。空手单件和磁铁九格都要尽力腾空，两边都塞不下就扔在目标旁边地上；拾取和休息室容器入库前实时复核世界权限，向玩家背包卸货只实时复核团队关系。任务未被认领时，所有者或当前同队成员的无休息室收集悦灵仍可在拆除/清场阶段自领标记掉落。

## 6. 寻路、并发、区块加载与规模

`128` 格是发现和休息室调度单段范围，不是让每只悦灵对 `257^3` 个方格做完整 A*。当前分层寻路：

1. 先用自身 `0.35 × 0.6` 碰撞箱按步进扫掠；直达无碰撞时不启线程。扫掠起点先拉回悦灵所在格的落脚点，吸附不成立时保持原姿态：停靠常有亚格漂移，包围盒会同时压住上一格，于是每一步扫掠都连带检测那一格的天花板并被整体否决，明明只差两格也规划不出路径
2. 受阻后主线程只捕获局部 `BlockState` 和已交付投影碰撞；工作线程按目标状态的真实 `VoxelShape` 编译碰撞并跑六向 AABB A*，交通预约不进入快照
3. 远距先在 `16×16×16` 区块段走廊上找下一段，区块段搜索最多扩展 `96` 个节点；再只对当前段做局部 A*，局部边界通常外扩 `16` 格且最多扩展 `65,536` 个节点，不一次展开 128 格柱。同一目标连续规划失败时交替改用直取最终目标裁出的局部目标：段级连通判定比实体尺度粗，选中的门洞可能根本挤不过去，重跑只会得到同一条失败计划
4. 失败则在快照上验证抬升绕行；再失败返回空路径并悬停/爬升，禁止对着墙直冲
5. 目标或自身嵌进已交付假方块时先 `snapToFree`
6. A* 必须从悦灵真实位置验证首段，转角压缩后的每一段再次扫掠；飞行中下一步被动态碰撞挡住、连续 `2 gt` 水平碰撞或连续 `20 gt` 未接近当前路点时按 `STUCK` 优先级重规划。旧碰撞标志只能失效当前路径一次，不能反复取消新请求；`verticalCollision` 在贴地滑行时很常见，不能当撞墙
7. 每个维度每 tick 最多捕获 `2` 份局部快照，单段局部目标限制在 `24` 格内；每只悦灵最多保留一个请求。搜索实时超过 `5` 秒、悦灵离快照起点超过 `4` 格，或请求满 `40 gt` 后偏离快照起点超过 `0.5` 格时作废；旧请求取消后，碰撞编译与 A* 扩展必须协作退出，不能与新请求并行耗尽 CPU
8. 任务规划覆盖表和蓝图外包络按布局版本缓存；租约或交付变化只失效候选腔体，不能重新构造整份目标覆盖
9. 已交付投影只在任务首次进入建造或服务端重载后全量恢复，此后随交付增量维护，不能每 tick 扫描全部操作
10. 操作按 ID、世界位置和父子关系建立运行时索引；状态摘要按变更版本惰性重建，建造分配游标越过不可逆的完成前缀，拆除剥离顺序按操作布局缓存，悦灵每 tick 恢复或领取任务不得重新线性扫描整份蓝图
11. 已加载工作悦灵按维度、服务器 tick 和所有者合并快照；加入/离开事件增量修正，同一 tick 的参与者、能力与磁铁检查不得重复扫描全部实体
12. 专用守护线程池大小为 `clamp(可用处理器数 / 2, 1, 4)`，优先级固定为 `ESCAPE > STUCK > DOCK_HEAD > DELIVER > PICKUP > LEAVE`；召回连续 `3` 次确认目标不可达后才强制贴靠，避免永久卡在封闭休息室外

现有 `AdhesivePathPlanner` 的异步快照流水线可以抄，但其 16 格牵引、20 格断裂、危险地形和斜体 SAT 不能带过来。悦灵使用独立线程池 `plasticraft-allay-path-search-*`。接近位、撤离段和休息室时隙由 `ConstructionTraffic` 运行时排他预约，只在选择最终工位或时隙时复核；包括这些预约在内的任何交通项都不得注入 A* 碰撞。狭窄走廊预约只作局部让行提示，也不得阻止另一个接近位复核。`AllayFlightNavigator` 只对其他施工悦灵做局部速度避让，正在取料、交付、拆除或收集的飞行优先于返航飞行；同类迎面冲突再按 UUID 确定唯一让行者。让行者选定侧向或垂直方向后保持 `8 gt`，并同时避开附近全部高优先级悦灵，避免双方对称摇摆或改道撞上第三只悦灵；单格通道没有合法避让方向时继续原路线，利用施工悦灵之间既有的无硬碰撞互相通过。避让使悦灵偏离规划线后，下一步碰撞检查和无进展计时必须从真实位置触发新快照，不能继续朝旧路点斜切方块边缘。

建设与拆除交互都要求悦灵碰撞箱到目标接近位不超过工具触及，并且工具到目标有无阻挡的交互线段；空手收集也必须实际飞到掉落物旁才可拾取，磁铁收集在 `16` 格内吸入。任务不是到达目标方块中心；规划器先枚举六个正交邻位，全部失败时才补查同一 `3×3×3` 邻域的边角位置，让悦灵可以从台阶、轨道或机器旁的斜上方伸手施工。所有回退位仍必须通过触及、`0.35 × 0.6` 真实碰撞、外部可达性和交通预约复核；非投影实体操作仍优先使用自身格。拆除阶段选择当前真实表面可达的位置，建造阶段优先选择放下假碰撞后仍属于外部可达空间的位置。未来工具的触及范围由工具定义声明。

多机协作由中央任务分配器控制：

- 同一操作只有一个租约：建设租约包含材料、目标、接近位、撤离段和超时，拆除租约独占目标，收集租约独占任务掉落物数量，观察租约独占九区块覆盖窗口和时段
- 休息室出库前必须再次确认当前阶段和当前层确有可分配操作；最低流体填充层尚未解决时，上层操作不算可并行前沿。完成撤离并卸空携带物或收集物后，绑定悦灵没有租约且当前没有可认领工作时立即回库，不能因为当前阶段理论上仍可使用其工种而留在工地
- 休息室顶部、取料位、撤离段和封口位置使用排他时隙预约，只阻止重复认领同一最终工位；任何预约都不成为 A* 硬障碍，狭窄走廊预约只参与局部让行
- 已租建设或封堵操作每 tick 复核安全接近点；原接近点失效且找不到替代位时当 tick 释放操作、接近点和交通预约，保留在途材料供返还或重新认领，不能继续朝目标上方空飞。`WAITING_OCCUPIED` / `WAITING_WORLD` 仍按既有阻塞等待语义保留租约
- 交付途中完整卡住一轮且既不在触及范围内、也不属于阻塞等待时才算一次“确认飞不到”，挑不出任何可用接近位同样计一次：先释放租约让别的悦灵换方向再试，同一操作累计 `4` 次后按台账把在途材料退回休息室或所有者，并把该位置退避 `200` tick。退避期间派发直接跳过这一格，其余位置照常施工；退避结束后任意悦灵可以重新取料、重新挑接近位。飞不到的位置永远留在建造阶段，既不作废也不计入残缺，绝不因此让任务收敛到完成；重新够得到目标即清零。只释放租约不足以脱困，托管台账仍记着在途材料，下一 tick 同一只悦灵会立刻重领同一操作，形成悦灵原地不动的活锁
- 剩余建造位置全部处于退避时才对外报 `UNREACHABLE` 等待原因，避免别处照常施工时误报；退避到期时间随游戏刻变化，因此这一判定每次实扫，不进状态摘要缓存
- 悦灵被真实方块或已交付投影整体包住时，`WorkingAllayEntity` 每 `20` tick 检测一次并用 `AllayFlightPlanner.escapeSolid` 逐圈找脱困点直接传送出去。碰撞钳制会把指令位移全部吃掉，只靠寻路永远出不来，而 `DOCKING` 状态下各施工行为直接 early-return，所以这一检测必须挂在 `aiStep` 服务端分支最前面，与飞行状态无关
- 优先级高的悦灵先通过，低优先级悦灵在宽处避让；单格通道没有避让空间时允许本就无硬碰撞的施工悦灵互相通过
- 悦灵被推离、路线改变或租约超时后，材料仍由台账追踪，目标可以重新分配但不能重复消耗

加载覆盖由观察悦灵独占，蓝图和其他工种不再隐式加载大面积世界。加载单位统一为 `ChunkPos` 表示的完整高度区块柱；一份观察覆盖是以观察悦灵或休息室所在区块为中心，连同水平八邻区形成的 `3 x 3` 九个区块，九个区块都必须取得能够让实体和方块实体正常运行的实体刻级区块票，不再设置任何 Y 向逻辑窗口：

- 已部署或活动蓝图本身不建立加载票；投影、台账和提交日志保存在世界级数据中，对应区块重新活动时再恢复碰撞与渲染
- 建设、拆除和收集悦灵即使正在执行任务也不建立加载票，只能在玩家、其他加载器或观察悦灵已经保持实体刻的区块内移动和工作
- 世界中的观察悦灵只在自身当前维度加载以所在区块为中心的九个完整区块；地下、高空和地表目标只要 X/Z 落在这九个区块内就使用同一覆盖
- 观察悦灵跨越区块边界时，先申请并确认新中心的九区块覆盖，再释放旧中心不再重叠的区块；依赖它的工人未进入新覆盖前不得越过旧覆盖边缘
- 无任务的观察悦灵交还给原版游荡，不强制离地四格；执行观察任务时可以停在调度器选定的任意无碰撞安全位置
- 不要用内部 FE 或休息室供电作为加载资格。世界中的观察悦灵只有在仍戴帽、手持望远镜且实体实际存在于该维度时才提供覆盖；摘帽、换下望远镜或实体已不在世界中时立即失去资格
- 休息室的 16 条有效托管记录中至少有一只手持望远镜的观察悦灵时，以休息室所在区块为中心建立同样的九区块覆盖，存放多只不叠加范围。资格只看托管记录与休息室是否仍有效，不看电网；普通箱子和玩家背包中的望远镜物品不加载
- 最后一只具备加载资格的观察悦灵出库时，休息室覆盖先与该实体的新覆盖原子交接再释放；观察悦灵入库时执行相反交接。交接期间不能让休息室、悦灵或跟随工人停止刻
- 观察实体与休息室的覆盖中心、维度、资格和引用计数保存在世界级加载索引中。服务器启动时由该索引先恢复符合资格的区块票，再等待实体或方块实体加载后校验；失效记录立即撤票，不能依赖尚未加载的休息室或悦灵自己唤醒自己

观察覆盖只存在于其当前维度，不跨维度映射，也不为其他维度建立远程票。系统不设置额外的每名玩家或每维度观察悦灵数量上限；每只符合资格的观察实体或每个符合资格的休息室各提供一份九区块覆盖，重叠区块用引用计数合并。单个蓝图任务既有的 `64` 只参与悦灵上限仍然有效，它不是观察票的独立全局上限。

中央任务必须支持执行中增量插入、移动和释放观察覆盖任务，不能在启动时一次性固定全部路线并永久加载：

1. 每次派发前查询取料点、路线和目标涉及的区块当前是否已由玩家、观察悦灵或其他原版/模组来源保持实体刻；已有覆盖时直接利用，不额外占用观察悦灵
2. 覆盖即将消失或下一项进入未覆盖区块时，把观察任务插入当前计划，先让观察悦灵到达并建立九区块窗口，再允许其他工种进入
3. 所有依赖工人离开后即可释放该观察任务，让悦灵移动到下一窗口、返室或恢复游荡；自然加载后来出现时也可以提前释放冗余观察任务
4. 任务休息室所在区块同样必须处于实体刻窗口内，才能执行库存访问、任务协调、入库、出库和远程转运。室内已有具备加载资格的观察悦灵时可自加载；否则先安排其他观察悦灵覆盖该室，再调度其中的建设、拆除或收集悦灵
5. 可用观察悦灵不足时不直接失败。调度器收缩后续并行前沿，重排尚未开始的操作，让其他悦灵结队跟随观察悦灵移动；必要时让同一只观察悦灵在安全停靠群与下一工作区之间往返搬运窗口
6. 完全没有可用观察悦灵且下一项所需区块也没有其他有效加载来源时，任务进入 `WAITING_OBSERVER`；任一外部加载来源出现或观察悦灵可用后立即重新规划

来源不可用时，普通工种悦灵在现有观察或外部覆盖释放前立即悬停；观察窗口可以转去执行其他路线，使该实体随区块卸载而停止刻。任务台账继续保留其 UUID、位置、租约和携带物。来源恢复后，调度器先用观察悦灵或外部来源重新覆盖落点、来源和后续路线，确认实体重新加载且台账一致后才允许继续；不能因为实体暂时未加载就复制其携带物或把租约发给另一只悦灵。

蓝图不设置一个类似 `128^3` 的玩法尺寸上限；要接近 Litematica 的大结构体验，内部必须按区块段使用局部调色板、稀疏位图、交付位集和增量材料统计，客户端只接收可见区段与进度差量，投影按区块段批量建网格。无限放置指不人为限制非活动蓝图数量，实际仍受世界边界、建筑高度、存档空间、内存和服务器管理配置约束，损坏文件声明的极端尺寸必须在分配内存前拒绝。

任务、流体封堵、拆除进度、任务掉落物、投影、观察覆盖计划和提交日志保存在世界级持久数据中；悦灵实体只同步渲染必需的安全帽、主手、携带物或收集库存、动作、飞行状态和短期状态。服务端异常重启后按日志恢复：已经真实放置的填充块和已经真实拆除的位置保持结果且不会重复派发，尚未发布的托管资源继续由台账持有；已进入发布点则完成剩余分区并只发布一次。不能出现已经拆除的方块被任务凭空复原，也不能出现真实半结构已经运行、任务却回到取料阶段的状态。

实现边界应至少分为：结构格式与规范快照、中央任务与材料台账、所有权服务与独立 FTB Teams 适配器、工具能力注册、流体封堵规划、拆除扫描与本体破坏适配器、任务掉落物追踪、施工投影索引、装配顺序规划、飞行与观察覆盖规划、休息室综合调度、方块/实体适配器、安静提交服务，以及纯客户端的悦灵/投影/菜单渲染。NeoForge 注册放在 `init`，客户端代码放在 `client`；公共任务逻辑不引用渲染类或 FTB Teams API。未来 26.1.2 迁移时只替换结构 API、区块票 API、`BlueprintProjectionTarget1211` 与分区渲染后端及注册适配层，不改任务语义或网络字段既有顺序。

## 7. 验收基线

后续实现至少需要覆盖以下验收场景。已由悦灵替换覆盖的条目以当前代码为准，不要用无人机物品或内部 FE 重验。

- 手持 `allay_hard_hat` 右击原版悦灵转换成施工悦灵；潜行右击摘帽转回原版，UUID、位置、名称和主手保留；手里还有托管物或收集物时不能摘帽
- 安全帽占地最大 `11×11 px`、高度最大 `16 px`，需要 3D 打印组件；空模型、超宽、超高被拒绝；戴上后按模型原尺寸渲染，水平中心对齐头顶中心，底面先对齐头顶再沉入 `1 px`
- 空手同时建设和近距收集；蟹钳建设触及 `4` 格且不捡掉落物；切石机只拆除；磁铁只收集并拥有九格；望远镜只维持区块覆盖，不领施工操作
- 碰撞箱 `0.35 × 0.6`，无硬碰撞，玩家不能站上去，但可以挤开或用拴绳牵走；空闲复用原版游荡，任务中由施工寻路驱动
- 取放拆收每 `4 gt` 最多 1 次，够到后先转向再动手
- 施工悦灵和休息室都不消耗 FE，也不向电网请求功率
- 蓝图声明区域内原本与目标相同的方块也先拆后建；拆除瞬间完成，其经验、战利品、多方块回调和不可破坏判定与 AnvilCraft 普通铁砧砸切石机上方方块一致，拆除悦灵始终不吸取物品
- 缺少拆除悦灵时“暂停”会等待并报告，“跳过”会保留障碍后继续；没有绑定休息室的世界悦灵固定暂停；基岩等永久障碍无论配置如何都不会阻塞整个任务，其目标位置直接跳过
- 协调室的清场二选一决定蓝图空白格上的世界方块是否拆除：默认拆除整片声明区域，另一侧只拆与蓝图实际放置方块重合的格；组合件按核心整体判断，封堵填充块两种模式都照常清走。未认领或未规划任务在下一次规划时读取当前设置；已认领且已规划任务切换按钮会立即同步未完成拆除台账，`CLEAR_AREA` 补入/恢复仍存在的显式空白格拆除，`KEEP_BLANK` 跳过这些未完成项，已完成拆除不恢复
- 玩家点击托管卡片手动放出的悦灵会清空 `homeLounge`、`origin_lounge` 和 `transit_job`，成为固定 `PAUSE` 的无休息室悦灵；死亡或死亡动画期间停止工种/回库调度，安全帽掉落受一次性保护，不能在同一死亡流程重复掉落或重新入库
- 建造期间在蓝图显式声明格新放置与目标不符的真实方块会立即暂停建设并追加拆除操作；`CLEAR_AREA` 清理显式空白格，`KEEP_BLANK` 保留显式空白格但仍清理实体目标格。拆除掉落带任务标记并进入正常收集/台账结算，匹配目标状态的外部方块直接满足对应放置操作
- 领地或权限拒绝无论配置如何都进入 `WAITING_PERMISSION`，恢复授权后续做；任务不能通过跳过或最终强制覆盖绕过保护
- 多个相邻水源和蓝图边界外持续流入的水先由真实临时填充块严格自下而上排掉并一次封住，再由拆除悦灵进入已清空格拆掉全部区内填充块；区外壳留到提交后再砸；任务不会逐格清水后被无限水源永远补回，也不会无边界追踪整片海洋，全部拆除完成前不会开始建造
- 流体封堵中途取消会立刻停止；已真实放下的填充块原样留在世界，未放置的在途材料返还，不出现取消后继续清理或无掉落删除
- 没有收集悦灵时，拆除掉落物留在原处且不阻塞施工；有收集悦灵时，只收本任务掉落物。九格只是临时库存，卸货后必须腾空，经过实体化、入库、重启后不丢失或复制
- 磁铁收集能沿连续掉落物在每次拾取后重新扫描当前 `16` 格；库存满后停止吸入并去卸货，向所有者背包或休息室下方容器转入可容纳的物品，两边都塞不下的扔在旁边地上，不收经验也不损耗磁铁耐久。空手收集必须飞到 1 格内才捡 1 个，再飞回同一类目标，满了同样扔旁边地上
- FTB Teams 安装、卸载、玩家入队和离队后，悦灵调度、任务访问和卸货权限都按当前关系更新；未安装时保持仅所有者模式
- 已交付的整方块、台阶、栅栏、打开/关闭的门等投影具有正确碰撞；建设悦灵能重新规划并从内部撤出后再封口
- 在完成前两层投影时取消 `3 x 3 x 3` 圆石任务，只把已交付的两层提交为真实圆石；已拆世界不恢复，在途建设悦灵立即返还材料且不完成当前交付，未交付层不生成
- 复杂红石蓝图包含原版红石粉、铁砧工艺红石导线端口、锁存器、比较器、中继器和稳定伸缩活塞，施工期间不运行，完整提交后在相同外部环境中恢复保存状态并执行原功能；本体导线端口写入覆盖表后，后续拓扑更新仍保持蓝图四向
- 沙、红石粉、火把、流体和其他脆弱状态无需逐块支撑分析也能在最终提交中出现；已交付红石粉不剔除其支撑方块的顶面；计划刻相位不列入一致性断言
- 原版 `.nbt`、Create `.nbt` 和多区域 Litematica `.litematic` 导入同一测试结构后得到一致的规范方块、方块实体和实体快照
- 部署、取消、分层、移动、旋转和镜像使用本系统新绘制的按钮；结构磁盘在任意菜单内由程序绘制黄色/绿色槽底且只通过右击启动，不存在启动按钮或启动图标
- 装满物品的容器、含流体机器、船、刷怪蛋生物、树脂捕获生物和带内容实体都只使用真实来源资源；创造模式不扣背包；取消、断线和缺料不复制或吞物，返还库存满时物品掉在来源旁
- AnvilCraft 大型方块在建设和拆除时都只处理一次核心控制器，其他 `part` 不重复消耗、放置或产生掉落
- 四个满载休息室最多共同派出 `64` 只四类悦灵；综合调度会根据各阶段瓶颈借入建设、拆除、收集或观察悦灵，只有缩短预计完工时间才转运，任务后返回同维度原休息室；被借入的悦灵在任务休息室只取放材料，不入库排队，任务休息室的顶部通道与托管位始终只服务本室悦灵
- 蓝图和三个普通工种不建立加载覆盖；每只符合资格的观察悦灵实体或休息室实际加载当前维度以自身为中心的 `3 x 3` 共九个完整实体刻区块，不限制高度，数量不足时安全接力
- 玩家或其他来源加载区域时不浪费观察悦灵；来源消失后任务能在执行中插入观察任务，缺少观察悦灵时重排后续操作并让工人结队跟随，休息室未覆盖时不会违规访问其库存
- 来源不可用时携带资源的悦灵立即悬停并保留租约；租约和携带物跨区块卸载、重启及覆盖释放后仍唯一，来源恢复时先重建九区块覆盖再继续
- 服务器重启、观察悦灵跨区块和实体/休息室形态交接时不会留下重复或失效区块票；新九区块覆盖未达到实体刻前不释放旧票
- 新增一个模拟未来工具定义时不修改悦灵实体类即可参与任务；多用途工具可以领取非拆除能力，永远不能被调度器当作切石机使用
- 异常重启不会留下无主填充块、投影、区块票、重复实体、重复掉落物或重复材料
- 破坏休息室会把托管和正在入库的悦灵生成回世界，并掉出结构磁盘
